# Pull Request: Core Platform Hardening, Creator Economics, and Accessibility Overhaul

## Overview

This comprehensive Pull Request addresses several critical epics across the EduVault marketplace. It hardens the upload and delivery pipelines for secure and reliable content distribution, introduces fair payout mechanics for creators, optimizes database query performance for large-scale collections, and brings critical user journeys into compliance with WCAG 2.2 AA accessibility standards.

## Issues Addressed

- **Closes #80**: Extend upload pipeline with storage fallback, checksum verification, and metadata validation
- **Closes #81**: Add secure file delivery for private and unlisted materials with signed access tokens
- **Closes #78**: Implement creator payout accounting, treasury fee, and scholarship credit support
- **Closes #95**: [PERF]: Replace offset pagination with stable cursor pagination and query budgets
- **Closes #94**: [A11Y]: Reach WCAG 2.2 AA across critical GrantFox journeys

---

## Detailed Changes & Fixes Made

### 1. Robust Upload Pipeline (#80)
- **Validation:** Implemented strict server-side validation for file types, size constraints, and metadata lengths before triggering Pinata pinning.
- **Reliability:** Added a fallback storage buffer and retry mechanics to gracefully handle Pinata API outages.
- **Integrity:** Introduced checksum tracking and content hashing for both uploaded files and metadata JSON payloads.
- **Traceability:** Ensured uploaded metadata schemas now consistently include exact file URLs, thumbnail URLs, and a stable IPFS content hash reference.
- **Testing:** Added comprehensive unit and integration tests covering upload failures, retries, and invalid inputs.

### 2. Secure File Delivery (#81)
- **Proxy Endpoint:** Created a secure server-side file delivery endpoint to proxy access to IPFS/Pinata content for private purchases.
- **Signed Tokens:** Implemented short-lived, signed download tokens and presigned URLs to prevent direct bookmarking or sharing of protected assets.
- **Entitlements:** Added strict entitlement verification before generating download tokens or streaming file content to clients.
- **Observability:** Added detailed audit logging for all download requests, invalid token usage, and denied access attempts.
- **Testing:** Added automated tests verifying that private content is completely inaccessible without matching purchase entitlements.

### 3. Creator Economics & Payout Accounting (#78)
- **Schema Updates:** Redesigned material and purchase schemas to support detailed payout accounting, including creator revenue shares and treasury fee calculations.
- **Revenue Splits:** Added backend and contract logic to configure dynamic revenue splits during material registration.
- **Credits:** Introduced support for scholarship credits and institution-issued access assets in the checkout flow.
- **Reconciliation:** Ensured all payout state changes are immutably captured in purchase records, allowing seamless reconciliation from on-chain events.
- **Documentation:** Updated platform documentation outlining treasury fee flows and how creators configure revenue splits.

### 4. Performance: Stable Cursor Pagination (#95)
- **Pagination Strategy:** Replaced legacy offset pagination with stable cursor-based pagination using a composite key `(created_at, id)` across payouts, applications, users, logs, and tickets endpoints.
- **Query Safeguards:** Added strict maximum page sizes, deterministic tie-breaking, and bounded query filters to prevent expensive runaway queries.
- **Indexing:** Deployed evidence-based composite indexes for common role, status, and date filters, accompanied by `EXPLAIN ANALYZE` query plans.
- **Optimization:** Eliminated N+1 query patterns during profile lookups by returning only required projection fields.
- **Testing:** Implemented query budgets and representative-volume performance tests to guarantee sub-second deep-page latency.

### 5. Accessibility (WCAG 2.2 AA) (#94)
- **Semantics & Focus:** Fixed semantic HTML structures, accessible naming, and focus order across login, auth, payout discovery, milestone management, and support pages.
- **Keyboard Navigation:** Ensured every interactive element is fully operable via keyboard with visible focus indicators. Implemented keyboard alternatives for drag-and-drop zones.
- **Focus Trapping:** Corrected focus trapping and restoration behaviors within dialogs, sheets, and wallet modals.
- **Screen Readers:** Added ARIA live regions to announce status changes, async operations, and form validation errors programmatically without stealing focus.
- **Audit:** Passed automated `axe` checks and completed documented manual testing with NVDA and VoiceOver across all major screen sizes.
